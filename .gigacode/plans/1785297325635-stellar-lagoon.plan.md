# План: Рефакторинг сохранения чекпоинтов через буфер CheckpointState

## Цель
Заменить стратегию "SCAN → UPDATE → UPDATE" на стратегию "создать буфер → заполнить → сохранить одним INSERT".

## Проблема текущей стратегии
1. При сканировании создаётся запись `actionType="SCAN"`
2. `CheckpointPassedDialog` обновляет на "QUESTION"/"INPUT"/"PHOTO"
3. Если диалог сработал раньше — потеря данных
4. Нужно искать запись по `checkpointId` вместо ID
5. Гонка между несколькими обновлениями

## Новая стратегия
```
Сканирование → CheckpointState (в памяти)
Диалог → заполнение полей CheckpointState
CheckpointPassedDialog → сохранение ВСЕГО в БД одним INSERT
```

## Шаг 1: Создать CheckpointState и буфер

**Файл:** `CheckpointState.kt` (новый файл)
```kotlin
data class CheckpointState(
    val checkpointId: String,
    val checkpointName: String,
    val checkpointAction: CheckpointAction,
    val roundId: Int,
    val scanType: String,          // "QR" или "NFC"
    val scanTimestamp: String,     // "dd.MM.yyyy HH:mm:ss"
    val sequenceIndex: Int,
    val isSequenceCorrect: Boolean,
    var answer: String? = null,           // QUESTION
    var inputValue: String? = null,       // INPUT
    var photoPath: String? = null,        // PHOTO
    var questionText: String? = null,     // QUESTION
    var inputTitle: String? = null        // INPUT
)
```

**Файл:** `SharedPrefsManager.kt` (добавить)
```kotlin
// Буфер временных состояний чекпоинтов (в памяти)
private val checkpointStateBuffer = mutableMapOf<String, CheckpointState>()

/**
 * Получить/создать состояние чекпоинта для буфера
 */
fun getCheckpointState(checkpointId: String): CheckpointState? {
    return checkpointStateBuffer[checkpointId]
}

/**
 * Добавить состояние чекпоинта в буфер
 */
fun setCheckpointState(state: CheckpointState) {
    checkpointStateBuffer[state.checkpointId] = state
}

/**
 * Удалить состояние чекпоинта из буфера после сохранения
 */
fun removeCheckpointState(checkpointId: String) {
    checkpointStateBuffer.remove(checkpointId)
}
```

## Шаг 5: CheckpointPassedDialog — сохранять ВСЁ в БД

**Файл:** `CheckpointPassedDialog.kt`

```kotlin
LaunchedEffect(checkpointId) {
    if (!hasIncremented) {
        val activeRoundIndex = manager.getActiveRoundIndex()
        
        // Получаем состояние из буфера
        val state = QrHandler.getLastCheckpointState()
        
        if (state != null && state.checkpointId == checkpointId) {
            // Сохраняем ВСЁ одной записью
            manager.shiftDatabase.addLogEntry(
                checkpointName = state.checkpointName,
                checkpointId = state.checkpointId,
                employeeName = /* получить */,
                roundId = activeRoundIndex,
                routeName = "Маршрут обхода",
                sequenceIndex = state.sequenceIndex,
                isSequenceCorrect = state.isSequenceCorrect,
                scanType = state.scanType,
                actionType = when (state.checkpointAction) {
                    CheckpointAction.QUESTION -> "QUESTION"
                    CheckpointAction.INPUT -> "INPUT"
                    CheckpointAction.PHOTO -> "PHOTO"
                    else -> "CHECKPOINT"
                },
                questionText = state.questionText,
                inputTitle = state.inputTitle,
                answer = state.answer,
                inputValue = state.inputValue,
                photoPath = state.photoPath
            )
            
            // Удаляем из буфера
            QrHandler.clearLastCheckpointState()
        } else {
            // Fallback: если буфера нет — создаём обычную запись CHECKPOINT
            manager.shiftDatabase.addLogEntry(
                checkpointName = checkpointName,
                checkpointId = checkpointId,
                // ... базовые поля
                actionType = "CHECKPOINT"
            )
        }
        
        // ... остальная логика (индекс, toast, dismiss)
    }
}
```

## Преимущества новой стратегии

| Старая | Новая |
|--------|-------|
| SCAN → UPDATE → UPDATE | Один INSERT |
| Поиск по checkpointId | Прямое обращение к объекту |
| Го��ки между обновлениями | Нет гонок — всё в одном объекте |
| Потеря данных при сбое обновления | Данные собираются до сохранения |
| Сложная логика fallback | Простая и понятная |
